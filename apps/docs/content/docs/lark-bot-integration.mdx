Connect a Multica agent as a Feishu Bot so participants can converse in authorized DMs or groups, including people without a Labrastro account. The agent clarifies and summarizes feedback, then uses normal tools to comment in its own name. Conversations and runs remain in the workspace.

Each Bot maps to exactly one agent. To use several agents in Feishu, connect a Bot for each of them.

## Connect a Bot

The agent's owner and workspace owners and admins can start a connection:

1. Open **Agents** and select the agent to connect to Feishu.
2. Go to **Integrations** and click **Bind to Feishu**.
3. Scan the QR code with Feishu and confirm the authorization.
4. Return to Multica. Once the page shows **Connected to Feishu**, authorize conversations below.


The QR code is a one-time credential; if it expires, generate a new one. An agent that is already connected no longer shows the scan entry point; to rename the Bot or adjust its permissions, click **Manage in Feishu**.

<Callout type="info">
New connections are currently open only for mainland-China Feishu. Existing international Lark connections keep working and can still be managed.
</Callout>

## Authorize conversations

After connecting the Bot, open its **Agent → Integrations** page or **Settings → Integrations**. Expand **Agent conversations**, enter allowed group and direct-chat IDs, and select **Authorize conversations**. The authorizer must manage and be able to invoke the agent. Permission covers the agent’s normal tools in the entire current workspace; everyone in the allowed conversations can provide input.

Participants do not need to bind a platform account. Member bindings can still locate personal notification recipients. Unconfigured conversations are refused. Editing or revoking consent invalidates old external runs; notification delivery consent remains separate.

## Hand work to the agent in Feishu

### Direct messages

Message the Bot directly. Consecutive messages stay in the same Multica conversation, and the agent's replies go back to that conversation.

### Group chats

Add the Bot to the group first, then `@Bot` and describe what you need. The Bot only responds to messages that explicitly @-mention it; when it runs, it draws on the recent context it can read in the current session.

### Discuss a task

Name the task or quote a notification sent by the Bot, then describe your feedback. The agent may ask for clarification before posting a summary to the appropriate discussion under its own identity. Messages are not immediately copied verbatim into comments.

`/issue` is conversation text, not a direct member command. A report question stays in this conversation; it does not automatically rerun the automation or create an issue. A bare “yes” or “continue” does not approve multiple changes. `/new` starts a new Chat and `/clear` starts fresh context; bare controls do not run the agent.

## Manage connections

Open **Settings → Integrations** to view the Bots connected in the workspace. Workspace owners and admins can disconnect them here; an agent's owner can also manage their own Bot from that agent's **Integrations** page.

After disconnecting, the Bot stops receiving new messages. Existing conversations and audit records are not deleted.

## Self-hosting setup

Multica Cloud needs no extra configuration. A self-hosted deployment must first set a key used to encrypt Bot credentials:

```dotenv
MULTICA_LARK_SECRET_KEY=<base64-encoded 32-byte key>
```

Generate one like this:

```bash
openssl rand -base64 32
```

Restart the API server, then connect the Bot from the agent's **Integrations** page. Keep this key long-term: if it is rotated or lost, existing credentials can no longer be decrypted and the Bot must be reconnected.

`MULTICA_LARK_HTTP_BASE_URL` and `MULTICA_LARK_CALLBACK_BASE_URL` exist only for special deployments such as proxies and testing; leave them unset in normal operation.

## Troubleshooting

- **No bind button**: confirm the current account is the agent's owner or a workspace owner or admin, and check that the self-hosting key is configured.
- **QR code expired**: close the dialog and start the connection again.
- **Conversation not authorized**: check its chat ID, saved consent, and the authorizer’s current membership and agent invocation rights.
- **The Bot doesn't run**: check whether the agent is archived and whether the [runtime](/daemon-runtimes) it uses is online.
