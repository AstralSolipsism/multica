# 智能体文件夹单独建表，小队文件夹在读取时派生

OL-1027 给智能体页加文件夹，并把每个未归档小队显示成小队文件夹。决定：智能体的自定义文件夹和放置另建 `labrastro_agent_` 前缀的表，不复用 skill 文件夹表；小队文件夹不存成文件夹行，读取智能体文件夹树时由 `squad` 和 `squad_member` 现算出来，只持久化每个小队文件夹被放在哪个自定义文件夹里。

## 理由

- **小队的写路径在上游。** 新建、改名、增删成员、换队长、归档都由上游的 squad handler 处理。存成行的小队文件夹要么在这些写路径里同步，每次上游同步都要合并这些改动；要么异步对账，存在不一致的窗口。读取时派生天然一致，不需要同步代码。
- **小队没有需要保存的内部结构。** 技能包文件夹要存成行，是因为包内子文件夹来自导入时的来源仓库，必须记下来；小队文件夹里只有成员，成员关系已经存在 `squad_member` 里。
- **两棵树的规则不同。** skill 文件夹表带着技能包的列和约束（包根、内部受管文件夹、带来源路径的放置），一个 skill 只在一个位置；智能体可以同时出现在多个小队文件夹里，受管内容的来源也换成了小队。共用一张表会让两套约束互相牵制，也会让已经验收过的技能包事务代码承担回归风险。

## 考虑过的方案

- **小队文件夹存成文件夹行**，在 squad handler 里同步：一致性要靠上游文件里的改动维持，上游同步成本高。
- **通用文件夹表加资源类型列**，skill 和智能体共用：省掉一份增删改代码，但要改技能包的表结构和事务代码。

## 后果

- 小队文件夹没有自己的 id，用小队 id 标识。
- 小队文件夹之间、小队文件夹和自定义文件夹之间都不受同级重名约束（小队名本来就允许重复）；自定义文件夹之间的重名约束不变。
- 小队归档后，它的位置记录不再生效：读取时忽略，下一次修改文件夹树时清理。小队不能取消归档，所以不需要恢复它的位置。
- 读取文件夹树时，小队成员按调用者能看到的智能体过滤，小队文件夹不会暴露调用者看不到的智能体。
- 如果将来小队文件夹需要自己的子文件夹，就要改为存成行，并迁移已有的位置记录。
